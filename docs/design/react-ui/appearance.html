03Token reference

  
Every variable is overridable on any ancestor, or through appearance.variables. Values below are the shipped defaults. Precedence: the SDK's inline values from appearance.variables beat the defaults; a stylesheet rule on an ancestor sets the same variable only when the key is not passed through appearance.

  
CSS variableLight defaultDark defaultColours / controlsappearance.variables key

  
derived rules · setting accent derives accentInk (auto contrast) and accentSoft (accent mixed 12% light / 24% dark into bg) · setting bg alone derives surface (95% bg + 5% text) and border (86% + 14% text) · setting text alone derives muted (62% text + bg) · radiusSm = round(radius × .64), min 2px · success/warning/danger keep their Soft twins.

05Contrast guardrail

  
The SDK never lets a custom accent produce an unreadable primary button. It computes WCAG contrast, picks the better of two inks automatically and logs once in development. Try the amber and the burnt orange swatches.

  

    

      

        
        
      

      

      

      
rule · ink = #ffffff if accent/#fff ≥ 4.5:1, otherwise whichever of #ffffff / #0b1419 is higher · warn if the best is still < 4.5:1 · an explicit accentInk is respected but warned about · accent vs window background is checked against 3:1 (focus ring, links, outlines).

07Estilos específicos

  
Colour and radius travel through variables. When a single part needs its own size or shape, three tools go further than classNames: the styles prop per slot, a handful of size tokens, and data attributes that host CSS can target. All three leave the SDK's behaviour alone.


  
7.1 · The styles prop, one object per slot

  

  
<FactaInvoiceDialog
  session={token}
  styles={{
    primaryButton:  { height: 52, borderRadius: 999 },
    downloadButton: { height: 64 },
    total:          { fontSize: 40 },
  }}
/>

  
keys are the slot names of section 4 · values are React style objects (numbers mean px) merged after the SDK's own styles, before classNames · a slot not in the sealed screen simply has no effect

7.3 · Data attributes for host CSS

  

    

      
What the markup carries

      
<div data-facta-slot="root"
     data-facta-state="sealed"
     data-facta-run="auto-close"
     data-facta-variant="dialog">
  <span data-facta-slot="total">$45.50</span>
  <button data-facta-slot="downloadButton">…</button>
  <button data-facta-slot="primaryButton">Listo</button>
</div>

      
    
        
  • data-facta-slot on every slot: root, overlay, header, title, body, footer, primaryButton, secondaryButton, downloadButton, countdown, stepper, fieldList, quote, statusIcon, total, identifiers, storageRow, attribution.
    • 
        
  • data-facta-state on the root: loading · review · issuing · sealed · contingency · rejected · failed · expired.
    • 
        
  • data-facta-run: manual · auto · auto-close. data-facta-variant: dialog · drawer · inline · sheet.
    • 
      

      
/* host stylesheet */
[data-facta-state="sealed"] [data-facta-slot="total"] {
  color: #c2410c;
}
[data-facta-slot="primaryButton"] { border-radius: 999px; }

      
No !important needed. The SDK's own selectors are wrapped in :where(), so their specificity is zero: any host rule with a class or an attribute wins, wherever it sits in the cascade.
